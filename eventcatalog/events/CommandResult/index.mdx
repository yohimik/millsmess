Return a correlated success, rejection or accepted operation.

## Responsibility

Producer: **Core, Socket, MediaEngine**. Consumer: **client, operator, Socket, Core, MediaEngine**. Delivery: **request-response**. Channel: **Reply**.

## Preconditions and effects

Reply over the originating authenticated request/connection. A result never grants authority beyond its resource. Accepted means durably scheduled; completed means committed. Rejected includes a code. Never route replies from an arbitrary client-supplied address.

## Ordering and idempotency

Authenticated request or connection + message type + caller. The trusted receiver derives identity from credentials and rejects tenant/region/cluster mismatches.

See the domain delivery contract for replay windows, payload-hash conflicts and admission expiry.

## Failure handling

Reject invalid, unauthorized, expired or unsupported requests with CommandResult. Use the same idempotency key after a lost response; transient retries use bounded exponential backoff and jitter. Credentials, SDP and tickets are never durable-broker messages.

An event is a fact or scoped reply; its receipt does not bypass authorization or ownership validation.
